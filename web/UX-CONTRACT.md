## 编辑页布局与面板

编辑页左侧操作列依次是 AI、项目列表、导出、分享、附件、下载列表、设置、debugTool（仅开发模式）和返回主页；后两项从标题栏迁入，debugTool 菜单在按钮右侧打开。默认收起右侧面板；EditPage 的 activePanel 保存互斥的 ai / projects / attachments 状态，再次点击对应按钮或关闭按钮收起。按钮用 aria-expanded 表达状态。桌面面板为非模态区域，键盘可进入，Escape 关闭并恢复入口焦点；关闭和切换面板保留 AI 草稿、对话实例以及项目目录展开与滚动状态，不中止正在生成的回复。

项目列表复用现有当前项目目录及文件操作，不扩展数据查询或权限范围。导出和分享复用原处理流程与权限。附件列表底部固定“添加附件”，复用现有上传、拖放、插入、预览和下载处理。

`src/utils/platform.ts` 的 isMobile 是手机模式入口；桌面窄窗口不改变设备判断，所有桌面宽度下的非模态面板均以绝对定位覆盖正文，不占用布局空间；展开、关闭和切换时正文宽度与位置保持不变，保留操作列。手机的三个面板均进入右侧 VoexDrawer，复用 VoexModal 的焦点管理、Escape、遮罩和滚动锁；不同时打开多个抽屉。关闭、Escape、遮罩点击恢复入口焦点，抽屉内确认和预览沿用原弹窗栈。切换文档时，已打开的项目文件列表保持显示，不收起、不重复执行展开动画，并保留目录展开及滚动位置；手机也沿用此行为，手机上的其他面板仍随文档切换关闭。离开编辑页时关闭面板，取消未保存离开确认保留当前页面。手机隐藏格式工具栏；插入附件后关闭抽屉回到正文，下载附件时关闭抽屉后在左侧按钮旁展示队列。

### Zen 模式

来源：用户明确要求。项目列表下方提供“进入 Zen 模式”，进入后隐藏目录、小地图、常驻格式工具栏及其他左侧按钮，只在操作列中央保留“退出 Zen 模式”。左侧原控件保留挂载，A / L / F 继续打开 AI、项目列表和附件；打开面板后正常聚焦面板，关闭回到可见的退出按钮。只在进入时收起一次右侧面板，之后允许再次打开；退出不恢复已关闭的面板。模式仅存在当前编辑页实例中，退出恢复用户原有显示偏好，不改正文、保存状态或历史。进入按钮使用 Z 图标，退出使用 X。设置新增“Zen 模式自动全屏”，对应 `userConfig.editorZenFullscreen`，默认开启并按账号保存；进入点击在首次 await 前只请求一次全屏，不在 fullscreenchange 中重复请求。关闭该偏好只影响之后进入 Zen；退出 Zen 时退出当前全屏，离开编辑页时释放由本次 Zen 请求的全屏。全屏根为 documentElement，保持弹窗与抽屉可用；请求失败仍完成 Zen 切换并显示 messageBox 提示。切换不重建编辑器，使用 100ms 淡出和 200ms 淡入，动画期间阻止误操作并保留滚动位置，结束后焦点进入当前模式的入口/退出按钮；prefers-reduced-motion 下立即切换。

## 编辑页加载与动画

来源：用户确认的正文与 AI 模型/对话区域骨架屏、侧栏两段动画策略。EditPage 复用 useDocumentPage 的 loading / editorReady；首次进入时，正文数据与编辑器初始化均完成才显示格式工具栏、左侧操作列与已选右侧面板；此后切换文件时左侧按钮栏和格式工具栏持续显示，工具栏等待新文件就绪期间禁用，正文单独显示骨架；已打开的项目文件列表不随随后切换文件的正文加载状态隐藏或重新进入动画。加载失败结束骨架并保留重试、返回主页入口，不将失败当作空文档。骨架使用可访问的加载状态，初次初始化隐藏整个编辑器；切换文件时保留禁用的工具栏，只隐藏并隔离未就绪正文。新文件使用独立编辑器实例，旧实例的就绪事件不得覆盖当前文件状态。正文隐藏滚动条但保留滚轮、触摸和键盘滚动；标题、工具栏和正文共用内容列左边距。

AI 模型读取显示模型控件骨架，首次对话读取显示消息骨架；请求失败恢复对应错误与重试入口。已有消息在刷新或加载更早记录时保留，骨架不遮盖已加载对话或模拟 AI 正在生成。

桌面侧栏展开 200ms，内容延迟 200ms 后用 100ms 从 opacity 0 到 1。手机抽屉滑入也为 200ms，标题与内容于最后 100ms 淡入。组件保留挂载和已有草稿；快速关闭或切换会取消过期进入状态，隐藏和进入期间禁止面板内容聚焦，进入结束后桌面恢复面板焦点、手机沿用抽屉焦点管理。减少动画偏好下去除过渡与额外焦点等待。动画参数只作用于编辑页，不修改其他弹窗的时序。

## AI 文档助手

AI 对话中的助手回复和思考内容使用 AIMessageMarkdown，只读复用当前 Milkdown CommonMark/GFM 解析及 DOMSerializer；每个助手面板共用一个脱离文档的解析实例，消息本身是静态 DOM，不逐条创建编辑器。支持标题、强调、删除线、列表、引用、链接、行内/围栏代码和表格；用户输入保留原文。沿用现有主题变量和紧凑字号，代码与表格独立横向滚动并支持键盘聚焦。原始 HTML 作为文本展示，链接只接受网页、邮件和电话协议，图片仅显示说明文字；不加载附件、图片预览、公式或流程图。解析初始化或单条内容失败时保留原文；消息排版更新沿用当前对话的自动滚动规则，面板卸载释放解析实例。Markdown 只影响展示，原始消息存储、审阅与文档编辑保持原有流程。

思考过程由 `AIEditorPanel` 使用原生 details/summary 展示在对应助手回复正文之前；生成期间默认展开，可用鼠标、Enter 或 Space 手动切换。模型调用结束、停止或失败时立即自动折叠，不等待回复保存或审阅关闭；折叠后仍可重新展开。provider 读取兼容 Chat Completions 的 reasoning_content 和 Claude thinking 文本块，按本轮多次模型响应累积，仅展示服务实际返回的文本；等待期间显示真实等待状态，无思考内容的响应结束后不保留空面板。操作记录仍独立显示。用户确认仅修改前端：思考文本仅保存在当前账号的 Pinia 会话缓存，不写入历史完成接口、localStorage 或文档正文，刷新后不恢复；后端保持非流式响应，思考内容按模型响应轮次更新。工具调用续轮保留原有 Claude blocks/signature，兼容接口按响应回传 reasoning_content。

来源：本次用户要求，后端接口见 `../voex-server-main/docs/AI-API.md`。桌面和手机均通过左侧 AI 按钮打开，配置存储在后端，支持 OpenAI Chat Completions 与 Claude Messages。`AIModelDialog`、`AIReviewDialog` 复用 VoexModal，`ai.styl` 负责该流程表单样式；配置弹窗内的模型、协议、输出参数和审阅文件复用既有原生 select 约定，接受平台 popup。当前模型入口位于对话输入框内，使用 VoexTrigger 向上展开、避让视口；选项复用原生 radio 的方向键选择，点击、Space 或 Enter 确认后收起，Escape 收起并恢复入口焦点，Tab 可进入底部的“配置模型”并继续到导出按钮。输入框内的导出图标通过 aria-pressed 和 active 样式切换本轮授权，默认关闭，发送成功创建轮次后复位。发送使用图标按钮，生成中替换为停止图标；保留 Enter 发送、Shift + Enter 换行与 IME 保护，但不显示快捷键提示和当前文档行。密钥遮蔽，可主动显示，保存后不回传；修改供应商地址或协议必须重新提供 Key。

`AgentToolRegistry` 是能力注册入口，未注册的能力不能调用。当前文档读取、精确替换、追加、全文修改、特殊内容插入只作用于独立 AgentDraft。创建和重命名由编辑页显式注册并进入同一审阅；导出需要用户激活本轮导出授权图标，通过注册回调导出已保存版本。工具参数按声明校验，最多 10 轮调用，支持中止。公式、表情和流程图直接生成原有文档格式，不弹出插入表单。

读取上下文和生成建议均不写文件。当前文档有未保存修改时等待正常自动保存；生成期间允许继续编辑，但旧建议不能覆盖后续内容。每条助手消息保留独立快照，内容冻结，状态单独更新。完成有修改的生成后默认打开只读审阅；取消、Escape 或关闭只关闭弹窗，保留消息中的审阅按钮，不更新文件、名称、版本或目录。再次打开始终展示该消息自己的快照。

审阅差异由官方 `@milkdown/kit/plugin/diff` 与 `@milkdown/kit/component/diff` 在独立只读 Milkdown 实例中呈现，复用现有正文 schema 与自定义块规则；不连接协同，不向原编辑器提交事务，不改写已保存快照。按用户确认只替换前端展示，隐藏逐条接受/拒绝，仍整份应用已保存快照；移除自写行级算法、Markdown 双栏表格、差异过滤和分页。文件切换与重试释放旧预览实例；加载和解析失败时禁用应用，错误可重试。空正文、新建文件、重命名及已应用快照保留原有含义。

点击“应用并保存”先检查本地未保存内容和版本，再由后端在同一事务内检查所有文件权限、revision、原名称和原正文。任一冲突均不应用整批修改；失败保留审阅和错误。成功后更新编辑器与目录，按钮改为“查看已应用修改”。后端按账号、审阅 ID 和内容摘要去重，网络结果不明时重试不会重复新建；收到 `replayed` 时重新获取最新正文，不回填旧快照。刷新目录失败不把已成功保存误报为应用失败。AI 导出生成已保存正文的 Markdown 下载，保留附件引用，不打包附件文件。

同一文件可创建多个独立 AI 对话。`ai_conversation_sessions` 按账号、文档保存会话，`ai_conversation_turns` 按会话保存对话及每条审阅快照；旧记录归入“历史对话”。会话列表按创建顺序倒序，每页 20 条，显式加载更多；首条指令折叠空白后取前 40 个 Unicode 字符作为标题。面板顶部的“当前对话”原生 select 负责切换，“新建对话”成功后留在该文件并聚焦新会话输入框；无会话时首次发送自动创建。创建失败保留草稿和同一个请求 ID 供重试，不重复建会话。切换保留各会话草稿，模型只接收当前会话消息；生成、保存和应用期间禁用新建与切换。会话选择与草稿仅存在当前账号内存中，刷新后读取服务端会话列表并默认打开最新创建的对话。发送前先保存用户指令，生成结束后一次保存回复、操作记录、错误与不可变快照；成功后才显示审阅入口。刷新或重新打开页面读取后端历史，已应用状态从同事务写入的 `ai_review_applications` 获取，客户端不能改写该状态或已完成快照。应用请求只提交审阅 ID，正文取自后端保存的快照，保留原 revision、文件名和正文校验。

Pinia 只缓存当前账号的服务端历史和暂存未保存的回复。接口按轮追加，不用整段历史覆盖；每页 20 轮、按递增序号游标加载，完整快照按需获取。历史加载失败保留错误和重试入口；回复保存失败保留相同 payload 重试，未保存回复不能应用，刷新前使用 beforeunload 保护。重复完成同一轮的相同 payload 返回既有结果，不同 payload 返回 409；多个窗口不能互相覆盖不同轮次，迟到读取不能降级本地已应用状态。中断生成只恢复已保存的指令及未完成提示，不自动重启模型调用。

重新读取历史、完整快照和应用时都校验当前账号及源文档访问权限；应用时重新校验修改目标的写权限。账号切换清除前端缓存并取消旧请求；源文档软删除时历史暂不可访问，彻底删除时对应历史由外键级联删除。浏览器不持久存储正文或 API Key。验收用类型检查、Lint、构建、隔离数据库 HTTP 与浏览器交互，不运行单元测试。

## 导航与数据

`/`、`/home` 与未匹配路由最终进入 `/home/recent`（`recent`），未登录先进入 `/login`。项目列表仅显示在 Home 侧边栏，不设置独立的所有项目页面；旧 `/home/projects` 地址按未匹配路由进入最近文件。具体项目路由为 `/home/project/:projectId/:folderId?`，`projectId` 必填，`folderId` 可选；缺少项目标识的目录跳转返回 `/home/recent`。团队为 query `team_key`；未指定团队时展示自己的个人团队，切换团队进入最近文件并重新加载侧边栏项目列表。直接打开项目时根据服务端返回的所属团队补齐 query。侧边栏列当前团队可访问项目，具体项目页面列根文件夹，文件夹仅列文件，不能创建子文件夹。编辑文件由 `/edit/:file_key` 唯一定位，不用 localStorage 选择文件。

无项目时展示明确空态，不通过 initialize 自动创建项目。创建项目由用户发起；文件从已授权的文件夹创建，落点及完整路径以后端返回为准。前端显示结果 1 秒后打开文件。离开创建页面后不被过期请求强制跳转。目录加载可重试，失败不能被当作“没有项目”。

## 编辑与删除

侧栏项目 item 复用 `VoexContextMenu`，提供创建文件夹、重命名和彻底删除项目；均按项目 `permissions.write` 控制，不以 `manage` 代替编辑权限。三点按钮在 hover、focus-within 或菜单打开时显示，无 hover / 触屏设备常显；按钮、右键、ContextMenu 键和 Shift+F10 打开相同菜单。重命名与创建复用 InputDialog，失败保留输入，成功通过 `teams.projectRevision` 同步侧栏和当前项目内容。所有项目删除先使用 ConfirmDialog，明确正常内容和回收站内容均会彻底删除、项目无法恢复，确认后发送 `cascade=true`。删除当前项目成功后进入当前团队的最近文件，删除其他项目不切换当前页面，已离开原页面的异步结果不强制导航。

`ProjectPage` 的文件夹和文件 item 支持右键、ContextMenu 键和 Shift+F10 打开公共 `VoexContextMenu`。三点按钮、点击或 ArrowDown 展开相同菜单；链接保留，触屏不依赖右键。菜单提供打开、重命名、移入回收站，文件额外提供详细信息，复用 permission store、命名弹窗与 ConfirmDialog。移入回收站先确认保留与恢复语义；文件夹确认同时说明内部内容一并移入回收站，确认后发送 `cascade=true`，不根据任意 409 自动重试。菜单的键盘、关闭、焦点恢复与视口避让仍由 `src/plugins/context-menu/` 负责。

最近文件汇总当前账号查看过的项目文件和分享文件，不按侧栏团队筛选。保留条数由前端通过 `limit` 参数决定，当前页面传 `40`；后端只校验正整数，不设置固定业务上限。传 `40` 则返回、保留最近 40 条，传 `60` 则返回、保留最近 60 条，数据不足时返回现有记录。列表不分页、不统计全部历史；按最后查看时间排序、同一文件去重。后端先返回最多 limit 条，再异步清理该账号多余的记录；清理沿用本次请求的 limit 并重新计算边界，保护并发期间刚查看的记录，失败后在下次请求重试。文件权限由每条记录的服务端结果独立决定：可编辑文件进入普通编辑页，只读分享访问复用 SharedFilePage 的受保护 `recent-file` 变体。文件授权独立于历史保留条数，分享凭证不存储到客户端，链接撤销不撤回已有账号权限；无权限的历史项保留名称快照与移除入口。

最近文件与 ProjectPage 复用 `FileList`，共享网格/列表偏好、刷新、状态与菜单交互；仍按查看时间排序，最多 40 条且不分页。菜单提供打开、删除记录、跳转文件目录、详细信息。读权限失效时打开与详情禁用并显示原因；没有项目读取权限时隐藏跳转文件目录。删除记录通过独立的 `recent-api.ts` 调用 `/api/recent-files/:fileKey`，不调用文档删除 API；确认说明原文件与附件保留，成功刷新，失败保留记录与重试入口。跳转目录前重新获取 metadata 并校验权限，防止使用已经失效的列表快照。

详情统一使用 `FileDetailsDialog`，每次打开读取专用 `/api/document/:fileKey/details` 或 `/api/recent-files/:fileKey/details`，不取正文、不增加最近访问记录。显示创建时间、修改时间、修改人；无项目权限时后端 `path=null`，前端完全省略路径一项。有项目权限时路径为 `/项目/文件夹/文件`，项目名跳项目根目录，文件夹名和文件名都跳文件夹目录，并保留真实所属团队。历史未记录修改人显示“未记录”，匿名分享修改显示“匿名用户”；不使用创建者冒充修改人。关闭/切换文件/路由离开时取消旧请求，错误支持重试。字段契约见 `../voex-server-main/docs/FILE-DETAILS-API.md`。

编辑器只列当前项目。文件夹展开/收起，文件链接导航，当前文件的祖先自动展开。切换、返回目录、浏览器前进后退均检查未保存内容；真实页面卸载使用 beforeunload。保存失败保留内容，保存期间禁止离开。文档正文与目录元数据分离加载。

文档和文件夹删除的行为由 `../voex-server-main/docs/trash_doc/frontend-integration.md` 定义：普通 DELETE 表示移入回收站，保留正文和附件关联，分享暂时不可用。删除当前打开文档成功后关闭协同会话、关闭文档并回到原目录；未保存修改的丢弃在确认中说明。项目 DELETE 仍为彻底删除，确认必须覆盖项目中的正常内容与回收站内容。最近记录移除与附件删除继续沿用各自独立 API。

## 回收站

`/home/trash` 接入工作台主导航。`team_key` 使用当前团队，`project_key` 可选，`limit` 为 20 / 50 / 100（默认 50），`page` 记录页码，均位于 URL；请求始终发送真实团队 key，避免仅传普通团队的 project_key 时误查个人团队。回收站内切换团队仍留在回收站，项目筛选与页码重置；切换项目或每页条数同样重置页码。列表 API 按当前项目写权限筛选记录；文件永久删除由创建者权限校验，父级批量删除不得包含其他人创建的文件。文件授权不授予项目管理权。

列表使用独立语义 table，展示名称、类型、所属项目、删除人、移入时间、服务端 expires_at 和操作；文件夹显示 document_count。列表不提供内容预览、关键词搜索、批量操作或清空入口。恢复到原目录，can_restore=false 的文档禁用恢复并提示先恢复原文件夹；文件夹恢复后刷新整页以重读关联文档状态。彻底删除复用 ConfirmDialog，文件夹确认覆盖全部内部文件（包括此前单独移入回收站的文件），默认焦点为取消。每次操作及不确定完成的请求均刷新列表与相关目录、最近文件；删除末页最后一项后按最新 total 回退有效页。加载、失败、空列表独立展示；旧范围请求中止、操作防重复、完成后恢复焦点。业务依据为上述 Trash 对接文档，不承诺到期瞬间完成物理清理。

## 权限和异步

权限真源是后端 JWT 身份、团队成员关系与资源授权。项目、文件夹和文件动作统一由 `src/stores/permission.ts` 解释服务端 DTO；直接读取当前响应，不持久缓存另一份权限，避免账号切换或刷新后残留授权。文件夹继承项目，文件优先使用服务端显式权限；文件编辑者可修改正文、重命名、使用 AI、操作附件及再次分享，目录按文件权限过滤；只有文件创建者拥有删除文件权限。删除个人查看记录独立于文件读写权限。creator 由服务器确定，并用于文件删除鉴权。所有者与管理员自动编辑全部项目；普通团队成员能创建项目，仅对有 write 权限的项目创建文件夹和文件。项目名称、删除与文件夹/文件修改检查 write；项目权限设置检查 manage。项目列表隐藏无 read 权限项目。文件夹没有权限设置入口，固定继承项目。

`/home/teams?team_key=…` 选择团队，`tab` 记录成员/申请/邀请/设置，列表每页 20 条，`page`、`teams_page`、`my_page` 位于 query。该阶段 API 返回已授权完整列表，前端分页有界渲染。成员增删、角色变更、审核、链接撤销、转让、退出、删除均等待服务端确认后更新，危险或授权动作使用 ConfirmDialog。个人团队允许邀请，禁止转让删除；所有者不能退出。普通团队删除仅允许无项目。

项目权限区分 inherit 与 restricted；空名单不会被当作全团队开放。弹窗复用 VoexModal，选择成员使用原生 checkbox；取消或路由离开未保存修改时确认丢弃。文件夹始终继承项目，文件分享不扩展为团队或项目权限。

`/join#TOKEN` 与填写团队编号复用 JoinTeamDialog，要求登录、填写申请信息、等待管理员审核。登录跳转仅把 `/join` 写入 return query，邀请凭证始终位于 hash，不进入 query、日志、通知或本地持久存储。新邀请只在创建后提供一次复制机会，默认遮蔽；Clipboard API 失败时支持显示后手动复制。自己的申请记录在团队管理页面可查询。

`/share#TOKEN` 为公开只读页面，自行尝试恢复会话，未登录仍可阅读。未登录且链接可编辑时右上角显示“登录可编辑”；登录/注册过程仅用 fragment 保留分享凭证。登录用户 GET 分享文件后，服务端把该链接的 read/edit 权限写入独立的 `document_access`，只读可升级编辑，重新访问只读链接不得降级。已有用户权限独立于链接及最近记录；撤销链接只阻止新的访问者通过它获权，不收回已授予权限。权限以登录账号和文件为键，不保存客户端凭证。

服务端返回 write 时 replace 到 `/edit/:file_key`，地址无 query/hash；最近文件编辑入口同样使用普通文件路由。编辑页统一使用 document、附件、AI 和分享接口，不区分分享来源，不包含 limitedAccess 或额外的分享保存模式。所有文件编辑者拥有相同文件操作能力，创建者额外拥有 remove 权限；删除文件由后端单独检查 creator，不能通过删除父文件夹、项目或永久删除绕过。父项目权限不随文件授权扩展；项目树只展示可访问的文件和所属文件夹。分享阅读页不包含编辑保存、草稿、冲突或未保存离开确认逻辑。

读请求取消或丢弃过期结果。创建/命名表单提交中禁止重复、关闭和再次提交，失败保留输入。错误、加载、空目录、成功均有独立状态。弹窗使用原生 dialog modal 行为，键盘焦点可恢复。通知使用 polite live region；重要加载错误保留页面内重试入口。

## 认证与资料

来源为本次用户明确需求与确认：账号最少 8 位、密码最少 10 位。前后端约定账号 8–64、密码 10–128 个 Unicode codepoint，任意字符，不 trim 或归一化；昵称 trim 后 1–64 个字符且必填，邮箱和手机号可空。账号可用性检查使用 300ms debounce、AbortController 和旧结果防护，IME 组合期间不检查或提交。密码强度仅提示，不增加强制字符种类规则。

`/login`、`/register` 为匿名路由，受保护路由先恢复会话；`/share` 公开路由自行尝试恢复，失败继续按链接权限访问。成功登录回到经校验的站内 return 路径。JWT access token 仅存内存，refresh 和私有资源读取由服务器 HttpOnly cookie 支持。401 仅 singleflight refresh 一次并重试，403 保留当前登录。刷新失败时在受保护页面使用同账号重新登录弹窗，编辑内容保留在原组件中，不清除编辑器与上传状态。

注册成功即锁定创建结果；选填头像在拿到会话后上传至 path=avator，再更新资料。头像失败只重试头像步骤，明确显示账号已创建，可直接进入工作台。头像选择仅接受 JPEG/PNG/WebP，最大 5 MiB，预览采用 object URL 并在替换/卸载时释放。上传资源 creator 由服务端返回。

资料页位于 `/home/profile`，头像置于资料内容第一位，不提供“保存资料”和“返回工作台”按钮。昵称、邮箱、手机号修改后在 blur 时校验并自动保存，仅在 blur 后显示该字段错误；输入时清除旧错误，IME 组合输入完成前不保存。头像选择或移除后立即保存，上传失败保留选择并可重试，上传成功后资料提交失败的重试复用已上传资源。更新请求串行发送，每项基于已保存资料提交，其他字段的未提交输入不随请求发送，旧响应不覆盖新输入。保存状态和错误在字段旁显示；加载或保存失败保留字段。离开、刷新或关闭资料页不检查保存状态、不等待保存请求，也不弹出未保存提示。退出登录保留操作确认，完成服务端注销后清除内存会话，确认文案不检查未保存资料。账户和密码不在本次资料修改范围。

## 图片尺寸与对齐

来源为本次用户确认：保留图片说明，统一支持图库、粘贴与拖入图片的等比例拖动缩放、宽度输入、左对齐/居中/右对齐和持久化。`src/views/edit/milkdown/image-resize.ts` 是 image 节点的 schema、NodeView、HTML/Markdown 尺寸与对齐往返的唯一入口，由 editor-content 注册，编辑页与分享页复用。

选中图片显示缩放手柄与宽度输入（16–10000 整数像素），点击应用或按 Enter 提交；IME 组合期间不提交。拖动仅预览，松开时提交一次可撤销 transaction；Escape、pointercancel、失焦、只读切换、删除和卸载取消未提交的缩放。宽度输入提供非拖动操作，手柄支持左右方向键（10px，Shift 为 50px）。原始尺寸清除 width，按容器显示原图；宽度不覆盖 alt/title，不写 localStorage 或另一套文档元数据，沿用正文自动保存。

未设置 width 和 alignment 的图片沿用普通 Markdown，设置任一值时输出转义 `<img>`；属性仅包含 src、alt、title、可选 width、枚举 data-align 及由枚举生成的固定 display/margin style。读取兼容段落内图片、独立图片、多图换行和原有 Markdown，复制粘贴 HTML 同样保留尺寸与对齐；HTML 恢复只提取已知属性并验证图片 URL，不渲染任意 HTML 或传入的任意 style。对齐只作用于当前图片，修改对齐可独立撤销；原始尺寸只清除 width，保留对齐。只读不提供修改控件，响应式显示不改写保存的宽度。

## Pexels 图库

工具栏“图库”与 `/` 菜单“Pexels 图库”打开同一弹窗。搜索与方向、颜色筛选是本次弹窗的临时状态，不写入路由或持久存储；无关键词时展示精选图，有筛选但无关键词时搜索“自然”，界面明确提示。搜索采用 300ms debounce，Enter 立即提交，IME 组合期间不请求；筛选变化、清空与关闭均中止旧请求并丢弃旧结果。每页 30 张，加载更多失败保留已加载结果并提供重试。选图按打开时的映射选区插入标准 Markdown 图片外链；取消不改正文，关闭回到编辑器。切换只读状态或卸载时取消弹窗，禁止旧弹窗写入。

方向和颜色沿用原生 select，接受浏览器/操作系统的 popup 外观与键盘行为；状态、错误与空结果使用中文。图片署名及来源链接指向 Pexels。Key 从本地 Vite 环境配置读取，通过 Authorization header 发送，不写入日志、URL 或客户端持久存储；当前前端直连会使 Key 可被浏览器请求查看。

## 附件下载

编辑页和上传调试页的附件下载统一推入全局 download store。分享阅读页移除附件列表、预览、下载及队列，仅保留正文图片所需的资源读取。编辑页下载列表使用按钮旁的 popover 变体，点击入口或新任务加入时展开，重复点击、点击外部或 Escape 收起；显式关闭和 Escape 恢复入口焦点，点击外部保留目标焦点。浮层自动避让视口，列表独立滚动。上传调试页保留附件底部的 inline 变体。两种变体复用同一队列状态、进度与操作。已有 NotificationBar 负责重复下载和失败提示，进度与失败原因保留在列表，进行中的任务优先展示。

最多并发 2 个传输，其他任务排队；排队、下载与交给浏览器期间按 hash 去重，结束或中止后可再次下载同一 hash。下载请求 timeout=0，使用独立 AbortController 中止；路由切换继续下载。总大小已知时显示百分比与字节数，未知时显示已接收字节与不定进度，不伪造百分比。

收齐文件后自动触发浏览器保存，待浏览器处理点击后在下一事件循环撤销 object URL，释放文件数据、请求来源和去重项。列表仅保留最多 20 条结束任务的文字/数字元数据，可清除；不保留 Blob、分享凭据或可重复使用的下载 URL。状态“已交给浏览器”表示已发起保存，实际保存结果由浏览器负责。失败或中止后从原附件入口重新下载。

## Dialog 注册与生命周期

所有 `*Dialog` 必须注册到 `src/stores/modal.ts` 并由 App 统一挂载，业务组件不再直接嵌入 Dialog 标签。`useDialog` 负责将调用方显示状态和响应式参数同步到 store、接收业务事件，并在关闭或调用方卸载时释放该调用方的会话。同类型弹窗重复请求沿用拒绝并通知取消的约定，不能覆盖已打开弹窗；参数更新保留当前实例，只有会话 key 改变才重建。

集中挂载不绕过 Dialog 内部的提交锁和未保存确认。关闭后恢复原入口焦点，卸载取消读取与定时任务；含草稿的团队申请和项目权限弹窗通过可撤销的 router 守卫保护导航，其他守卫取消导航时保留弹窗。文件预览也通过 modal store 管理，previewer 只负责准备文件与触发显示。

## 编辑器表格、代码块与末尾输入

## AI 富文本附加控件

来源：用户要求接入横/纵卡片、文字颜色/背景色、图片尺寸与对齐。`src/agent/rich-editor-tools.ts` 注册 `read_editor_components`、`insert_card_list`、`update_card_list_layout`、`set_text_style`、`set_image_layout`，通过现有 `registerEditorTools` 向所有已支持的模型协议暴露，不新增页面入口或后端接口。参数校验由 AgentToolRegistry 递归检查对象、数组、必填项、枚举和整数范围，禁止额外字段。

组件清单基于目标 AgentDraft 最新正文，正文图片和卡片列表分别从 1 编号；卡片里的图片不算正文图片。清单返回 components_version，所有按编号的修改及引用图片创建卡片必须校验该版本和正文快照；草稿发生任何内容修改后应重新读取，过期编号不得改到其他组件。

卡片支持 horizontal（每行最多 4 项、自动换行、space-between）和 vertical（左图右文），总项数不限。items 的 title 自动加粗，text 仅作为纯文字并支持换行；可引用已有正文图片编号，复制引用时保留原图，不上传或生成图片。不能保存到卡片的临时/相对图片源会明确报错；无图时保留空位。整组图片宽度默认 160px（image_size，80–320 整数像素），高度默认 100px（image_height，40–640 整数像素），分别映射当前 schema 的 imageSize / imageHeight；修改布局或尺寸保留其他现有属性、所有项和文字格式。after_text 定位唯一可见文字，在其所在顶层块之后插入，默认追加到末尾。

文字样式按同一段内的可见文字定位，支持跨加粗/链接片段及完整 Emoji 的位置映射，不跨图片、附件、公式或不同段落。默认必须唯一；occurrence 指定第几处，0 只在明确要求全部时使用。font_size 支持 8–96px、0.5px 步长，0 只清除局部字号；复用共享 normalizeFontSize 校验，字号只改文字节点。text_color / background_color 支持 #RGB、#RRGGBB 或 none（清除该种颜色）。字号、前景色和背景色可以组合设置或分别清除，保留粗体、链接等其余 marks；代码块和行内代码不应用这些样式。

正文图片通过最新清单编号设置宽度（16–10000 整数像素，0 恢复原始尺寸）和 left / center / right / inline（清除对齐），保留地址、说明、标题与其他格式。image_index=0 仅用于明确要求全部正文图片。卡片内图片由整组统一调整，不单独改尺寸或对齐。

所有修改复用共享 Markdown codec 与 ProseMirror Transform，完成校验、序列化和再解析后一次写入隔离 AgentDraft；失败不产生部分修改，不改变真实编辑器或附件。沿用 1 MiB 草稿限制、审阅快照、服务端权限/版本检查及应用流程，AI 不能声称已保存。


## 局部字号

来源：用户明确要求类似 Word 的局部字号调节，并指定 px。编辑器沿用固定与浮动格式工具栏，在颜色入口前增加带中文名称的原生字号 select，接受系统选项弹层；提供默认及常用 px 字号，混合选区显示“混合”。只修改选中文字或光标后续输入的 fontSize mark，不改变段落、标题级别和全局字体；代码区、行内代码与非文字组件不应用字号。选择“默认”只清除字号，保留其他格式。每次选区字号操作独立撤销/重做，沿用 Yjs 协同与权限锁。

## 富文本存储格式

字号、文字颜色和背景色改为统一的 `<span data-voex-rich="1">…</span>` 受控片段。包含这些局部样式的段落、标题和表格单元格，其完整行内内容以明确 HTML 标签保存粗体、斜体、删除线、链接、行内代码、表情、图片和换行，不与 Markdown 强调标记交叉嵌套；不含这些局部样式的内容继续使用普通 Markdown。卡片正文仍在卡片 JSON 中保存原有 marks，选中文字复制时采用同一富文本规则。

本次是破坏性格式调整，按用户明确要求移除旧裸字号/颜色 span 的 Markdown 解析，不提供兼容分支或数据迁移。浏览器 HTML 粘贴继续通过各 mark 的受控 DOM 规则读取。共享 `rich-text.ts` 负责新格式的唯一读写；只接受生成规则中的标签、属性、颜色、字号和安全链接/图片，绝不将任意 HTML 注入页面。

AI 保存草稿前要求新 Markdown 再解析后的文档与修改结果结构相同；不能完整恢复时拒绝本次修改，不写入部分结果。

富文本换行明确记录 hardbreak 的 isInline 属性，软换行与实际换行分别恢复；AI 文字定位将软换行视为显示空格，实际换行视为换行符。


## 编辑器视频与音频块

视频和音频复用现有附件上传、列表插入和鉴权读取。展开时为独立组件，只显示播放器或加载状态，不保留附件卡片的图标、文件名和预览栏；默认按正文可用宽度的一半插入。选中后沿用图片的宽度输入、缩放手柄、左/右/居中对齐与“显示为附件”浮动工具栏，不提供“原始尺寸”。视频按实际画面比例缩放，音频只调整宽度，原生控件高度不变；右对齐时手柄在左侧。附件卡片提供“显示为视频/音频”，双向切换复用同一附件并保留尺寸、对齐；不删除文件。

共享 attachment schema 以可选 data-display、data-width、data-align 保存展开状态、16–10000px 整数宽度与对齐。旧附件格式继续解析，既有音视频默认独立展开；解析只接受受控枚举和尺寸。编辑器、共享 codec、协同持久化和只读阅读共用该规则。尺寸与切换写入可撤销的节点事务，无关事务、尺寸和对齐变更不得重载播放器或重置进度。

展开后自动加载原生播放器，不再要求二次点击“加载”，但不自动播放；失败可重试、加载可取消，只读时允许播放并隐藏编辑控件。缩放支持拖动及方向键，拖动期间预览、结束后一次提交，Escape、权限变化和卸载取消未提交拖动。输入校验、浮层定位和键盘行为沿用图片；不拦截原生播放器的播放、进度、音量和全屏操作。文件变更、附件不可用、收起或节点卸载时中止请求并释放 Blob URL，迟到结果不得写回；正文不保存 Blob URL。
